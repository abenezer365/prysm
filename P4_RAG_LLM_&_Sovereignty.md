# PHASE 4 — RAG + LOCAL LLM + DATA SOVEREIGNTY

## ROLE

You are implementing Phase 4 of Prysm Intelligence.

Assume Phases 1–3 are complete.

Before changing anything, read the current project state/memory files and inspect the existing RAG, LLM, AI-output, and knowledge-related implementation.

Use the repository as the source of truth.

---

# 1. PRIMARY OBJECTIVE

Build the Prysm reasoning layer so that structured intelligence produced by Phase 2/3 can be turned into useful, evidence-grounded investigator explanations using a **locally hosted LLM**.

The core flow is:

```text
Prysm intelligence
↓
structured evidence
↓
relevant knowledge retrieval
↓
local LLM
↓
grounded explanation
```

The LLM is the **reasoning/explanation layer**, not the primary fraud detector.

---

# 2. FIRST INSPECT THE CURRENT IMPLEMENTATION

Trace:

```text
AI result
→ evidence
→ current RAG
→ current model
→ prompt/context
→ response
```

Identify:

* what already exists
* what is reusable
* what is incomplete
* where sensitive data currently travels
* where third-party model/API dependencies exist
* how knowledge is currently stored and retrieved

Do not replace working components without understanding their dependencies.

---

# 3. LOCAL LLM

Move Prysm toward a locally hosted LLM suitable for the project's environment.

Choose the model/runtime based on the actual repository, available hardware and project requirements.

The implementation should make the model source explicit and replaceable.

Do not select a model merely because it is popular.

Prioritize:

```text
local execution
reasonable resource requirements
good instruction following
structured output capability
sufficient reasoning quality
```

---

# 4. EVIDENCE-GROUNDED REASONING

The LLM should receive the structured evidence generated by Prysm's intelligence layer.

It should be able to explain:

* what was detected
* which signals contributed
* what entities/transactions/relationships are involved
* why the case was considered unusual
* what evidence supports the finding
* what remains uncertain

The LLM must not invent evidence.

Do not allow it to silently override the model/rule/graph results.

Keep the distinction between:

```text
detected evidence
```

and

```text
LLM-generated explanation
```

---

# 5. RAG

Implement/refine retrieval so that the model can access relevant project knowledge when an explanation requires context.

Inspect the existing knowledge sources and choose an appropriate ingestion/retrieval design.

The retrieval layer should:

* retrieve relevant information
* provide source/context information to the model
* avoid unnecessarily sending the entire knowledge base
* remain reproducible and inspectable

Keep operational investigation data separate from general knowledge used for contextual reasoning.

---

# 6. KNOWLEDGE INGESTION

Establish a clear path for adding knowledge to the RAG system.

The system should make it possible to know:

```text
what was ingested
where it came from
when it was ingested
how it is represented
how it is retrieved
```

Do not build an unnecessarily complicated document-management system.

---

# 7. DATA SOVEREIGNTY / PRIVACY

This is a core requirement of the phase.

Inspect the complete reasoning path and identify any point where sensitive Prysm data could leave the controlled environment.

The intended architecture should avoid sending sensitive investigation information to third-party model providers.

Address, where relevant:

* local model execution
* access boundaries
* prompt/context exposure
* RAG data exposure
* logging
* credentials/secrets
* knowledge ingestion controls
* auditability
* unnecessary data retention

Do not claim that local inference automatically means legal compliance.

The goal is a technically defensible architecture with a clear data boundary.

---

# 8. STRUCTURED OUTPUT

Prefer structured model output where useful so downstream systems can reliably consume it.

The response should be separable into concepts such as:

```text
finding
evidence
reasoning
uncertainty
recommended investigation direction
```

Use the format that best fits the current project.

Do not build a fragile parser around free-form text if a more reliable structured interface is practical.

---

# 9. CONVERSATION / INVESTIGATION CONTEXT

Support the reasoning workflow needed by Prysm investigators.

The system should be able to maintain the necessary context for an investigation without indiscriminately storing or exposing sensitive information.

Do not implement the full backend conversation system in this phase.

Only establish the reasoning-layer requirements and interfaces needed for Phase 5.

---

# 10. EXPLAINABILITY

A good response should allow an investigator to trace:

```text
Why is this suspect risky?
↓
Which intelligence engines contributed?
↓
What evidence was found?
↓
What does that evidence mean?
```

The LLM should explain evidence rather than manufacture a conclusion.

Uncertainty must remain visible where evidence is insufficient.

---

# 11. TESTING

Test the reasoning layer with real outputs from the Phase 2 intelligence engine.

Verify that:

* evidence is preserved correctly
* retrieved context is relevant
* the LLM does not invent unsupported facts
* explanations remain grounded in the supplied evidence
* sensitive data does not cross the intended boundary
* local inference works reproducibly

Use known benchmark scenarios from earlier phases.

Do not evaluate this phase only with hand-written fake examples.

---

# 12. DO NOT IMPLEMENT PHASE 5 OR 6

Do not redesign the backend.

Do not migrate the backend to MERN in this phase.

Do not redesign the frontend.

Do not perform the final content/UI pass.

Only expose the interfaces that Phase 5 needs.

---

# 13. KEEP THE IMPLEMENTATION SIMPLE

Prefer:

```text
clear retrieval
+
clear evidence context
+
local model
+
structured reasoning
```

over a complicated multi-agent or multi-model system.

Do not add agents, vector databases, orchestration layers, or other infrastructure unless the actual project requires them.

---

# 14. ACCEPTANCE CRITERIA

Phase 4 is complete when:

1. Prysm can pass structured intelligence evidence into the reasoning layer.
2. A local LLM can process that evidence.
3. Relevant knowledge can be retrieved when needed.
4. The generated explanation remains grounded in supplied evidence.
5. The architecture clearly separates detection from reasoning.
6. Sensitive investigation data remains inside the intended controlled boundary.
7. Knowledge ingestion/retrieval is reproducible and inspectable.
8. The reasoning layer has a clear interface for Phase 5.
9. Existing intelligence results remain unchanged and traceable.
